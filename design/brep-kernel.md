# 정밀 형상(B-rep) 커널 — 설계

상태: **초안, 결정 대기** (2026-11). 작성 근거는 이 저장소의 코드와 2026년 11월 기준 외부 프로젝트 상태.

## 1. 목표와 범위

Kreate의 설계 기능(스케치·피처·도면·STEP)은 모두 **메시** 위에서 돈다. 이 문서는 피처 바디를 정밀 형상(B-rep: 면·모서리·꼭짓점과 그 위의 해석 곡면·곡선)으로 계산하는 경로를 들이는 계획이다.

얻고자 하는 것:

1. **정확한 STEP 내보내기** — 원통은 원통으로, 필렛은 토러스/스플라인으로. 받는 CAD가 구멍을 구멍으로 인식한다.
2. **선택한 모서리 필렛·모따기, 면 구배** — 위쪽 피처를 고쳐도 같은 모서리를 다시 찾는 영속 명명(persistent naming).
3. **정확한 측정과 도면** — 도면의 원·호가 다각형이 아니라 원·호로, 숨은선이 샘플링이 아니라 해석적으로.
4. **불러온 STEP의 정밀 형상 유지** — 지금은 읽는 즉시 삼각형으로 바뀐다.

범위 밖: 메시 기반 기능(스컬프트, 리메시, 모디파이어 스택, 렌더링)은 그대로 메시다. B-rep은 **피처 바디와 STEP 부품**에만 쓴다.

## 2. 현재 구조 (출발점)

| 영역 | 지금 | 파일 |
|---|---|---|
| 스케치 곡선 | 정밀(`Curve2D`: 선·원·호·타원·스플라인) | `crates/kreate-geom2d` |
| 피처 → 바디 | 곡선을 0.01 mm 현으로 쪼개 메시 돌출/회전, 합치기·빼기는 메시 불리언 | `crates/kreate-scene/src/feature.rs` (`solid`, `body`) |
| 라운드·쉘 | 바디 메시의 **모든** 날카로운 모서리 / 방향으로 고른 면 | 같은 파일, `kreate_mesh::modifiers::bevel`, `mech::shell` |
| 스윕·로프트·판금 | 메시 | `feature/shapes.rs`, `kreate_mesh::mech` |
| 바디 캐시 | 피처·참조 객체로 키를 만든 메시 캐시 | `kreate_scene::modifier` (`body`) |
| STEP 쓰기 | 다면체 B-rep(면마다 평면 다각형) | `crates/kreate-io/src/step.rs` |
| STEP 읽기 | 해석 곡면을 읽어 즉시 삼각화 | `crates/kreate-io/src/step_read.rs` |
| 도면 투영 | 메시 모서리 투영 + 광선 샘플링 숨은선 | `crates/kreate-io/src/drawing.rs` |
| 저장 | 피처는 "레시피"로 저장(형상 자체는 저장 안 함) | `container.rs` `FeatureRecord` |

중요한 점: **피처는 레시피로 저장된다.** 그래서 계산 엔진을 바꿔도 파일 형식은 바뀌지 않는다. 이전(migration)이 거의 필요 없다는 것이 이 작업의 가장 큰 이점이다.

### 라이선스가 결정을 가른다

`deny.toml`의 허용 목록은 MIT·Apache·BSD·MPL 등이고 LGPL은 없다. OCCT를 쓰려면 둘 중 하나다:

- **(a) 정책 변경**: LGPL-2.1을 허용하고 OCCT를 **동적 링크**(LGPL 의무: 교체 가능한 공유 라이브러리로 배포, 고지)로 넣는다.
- **(b) 런타임 로드 플러그인**: OIDN을 들인 방식처럼, OCCT를 별도 공유 라이브러리로 두고 있으면 쓰고 없으면 기존 메시 경로로 돌아간다. 빌드 의존성은 없다. 다만 C++ API를 런타임에 부르려면 C 래퍼 계층을 직접 만들어 함께 배포해야 해서 작업이 크다.

순수 Rust 후보(truck 계열)는 정책 변경 없이 바로 들일 수 있다.

## 4. 권장안

**2주짜리 비교 스파이크로 고른다. 기본값은 truck 계열, 기준 미달이면 OCCT(정책 변경 승인 시).**

이유:
- 라이선스·빌드·배포·wasm 원칙(메시 커널은 wasm으로 간다는 이 저장소의 원칙)을 깨지 않는 쪽이 truck이다.
- 다만 필렛·쉘의 견고성은 실제 형상으로 재 봐야 안다. 그래서 **같은 시험 묶음**을 두 후보에 돌려 숫자로 결정한다.

스파이크 시험 묶음(통과 기준):

1. 판 + 구멍 4개(돌출·빼기), 보스 합치기 → 닫힌 솔리드, 부피 오차 1e-6 이하.
2. 위 형상의 선택 모서리 4개 필렛 R2 → 성공, STEP AP214로 써서 FreeCAD에서 열었을 때 원통면·토러스면이 그대로 인식.
3. 쉘 두께 2 mm(윗면 개방) → 성공.
4. 회전체(컵) + 스윕(파이프) + 로프트(사각→원) → 성공.
5. 기존 `tests/` 의 STEP 샘플 읽기 → 정밀 형상 유지.
6. 3개 OS CI 빌드 시간, 바이너리 크기 증가, 위 1~4의 계산 시간.

두 후보 모두 기준 미달이면: 메시 경로를 유지하고 **정확한 STEP 내보내기만**(단일 돌출·회전 바디 한정, 불리언 없는 경우) 따로 구현하는 축소안으로 간다.

## 5. 구조

```
kreate-scene::feature  ──(피처 레시피)──▶  kreate-brep (새 크레이트)
                                             │  trait Kernel { extrude, revolve, sweep, loft,
                                             │               boolean, fillet, chamfer, shell,
                                             │               draft, tessellate, step_write, step_read }
                                             ├─ backend: truck (기본)
                                             └─ backend: occt (기능 플래그 / 플러그인)
                    ◀──(삼각화된 메시 + 면·모서리 ID)──
```

- **새 크레이트 `kreate-brep`**: 커널 trait과 백엔드. `kreate-mesh`는 건드리지 않는다(wasm 원칙 유지). `kreate-scene`이 이것에 의존한다.
- **바디 평가**: `feature::body`가 커널이 있으면 B-rep으로 계산하고, 화면용 메시는 삼각화로 얻는다. 커널이 실패하면(불리언 실패 등) **지금의 메시 경로로 대체**하고 피처 목록에 경고 표시. 사용자가 모델을 잃지 않는다.
- **캐시**: 바디 캐시가 메시와 함께 B-rep 핸들을 갖는다. 파일에는 저장하지 않는다(레시피에서 다시 만든다). 큰 모델의 열기 속도가 문제가 되면 나중에 `.brep` 캐시 항목을 컨테이너의 선택 항목으로 추가.
- **삼각화 메시에 면 ID**: 각 삼각형이 어느 B-rep 면에서 왔는지 속성으로 붙인다. 이것이 화면에서 면·모서리를 고르는 바탕이다.

### 영속 명명(모서리 필렛의 핵심)

모서리를 번호로 저장하면 위쪽 피처가 바뀔 때 번호가 바뀐다(토폴로지 명명 문제). 방식:

1. **생성 이력 기반 이름**: 각 면은 "피처 k가 스케치 곡선 c로부터 만든 옆면", "피처 k의 시작 캡" 같은 이름을 갖는다. 모서리는 두 면 이름의 쌍. OCCT는 `BRepTools_History`, truck은 직접 추적.
2. **기하 대체**: 이름으로 못 찾으면, 저장해 둔 모서리 위의 점·방향에 가장 가까운 모서리. 지금 영역 시드·판금 모서리 점과 같은 방식이라 일관된다.
3. 둘 다 실패하면 그 필렛은 건너뛰고 피처 목록에 "모서리를 찾지 못함" 표시.

`FeatureRecord`에는 `edges: Vec<EdgeRef { name: String, near: [f64; 3], dir: [f64; 3] }>`를 추가한다(옛 버전은 1단계에서 넣은 `foreign_features`/`extra` 보존으로 잃지 않는다).

## 6. 단계와 완료 조건

| 단계 | 내용 | 완료 조건 | 기간(감) |
|---|---|---|---|
| **P0 스파이크** | 4장의 시험 묶음을 후보 2개에 실행, 라이선스 결정 | 숫자로 된 비교표, 커널 결정 | 2주 |
| **P1 토대** | `kreate-brep`, 돌출·회전·불리언을 커널로, 실패 시 메시 대체, 설정으로 켜고 끄기 | 기존 피처 테스트 전부가 커널 경로로도 통과(부피·경계 일치) | 4~6주 |
| **P2 정밀 STEP** | 피처 바디를 해석 곡면 STEP으로 쓰기, 읽은 STEP을 B-rep으로 보존 | FreeCAD·Fusion에서 원통·평면이 해석 곡면으로 인식(실제 파일로 확인) | 3~4주 |
| **P3 모서리·면 피처** | 영속 명명, 선택 모서리 필렛·모따기, 면 구배, 구멍 피처 | 위쪽 스케치 치수를 바꿔도 필렛이 같은 모서리에 유지되는 테스트 | 4~6주 |
| **P4 도면** | 도면 시트가 B-rep 모서리를 투영(원은 원으로), 해석적 숨은선, 단면도 | 도면 PDF/DXF의 구멍이 원 엔티티 | 3~4주 |

## 7. 위험

| 위험 | 대응 |
|---|---|
| 순수 Rust 커널의 불리언·필렛 견고성 부족 | P0에서 숫자로 확인; 실패 시 메시 대체가 항상 있음 |
| OCCT 선택 시 라이선스·빌드·크기 | 정책 결정을 먼저; 동적 링크 또는 플러그인 |
| 계산 시간(B-rep이 메시보다 느림) | 바디 캐시, 드래그 중에는 메시 경로로 미리보기 후 놓을 때 B-rep |
| 두 경로(메시/B-rep)의 결과 차이 | 같은 테스트를 두 경로에 돌리는 패리티 테스트(경로 추적기 HW/SW 패리티와 같은 방식) |
| 범위 팽창 | 단계별 완료 조건 밖은 다음 단계로 |

## 8. 결정이 필요한 것

1. **라이선스 정책**: LGPL(OCCT)을 허용할 수 있는가? — 허용하지 않으면 후보는 순수 Rust 계열로 좁혀진다.
2. **배포 크기**: 앱 크기가 수십 MB 늘어나도 되는가? (OCCT 선택 시)
3. **P0 스파이크 진행 여부**: 2주 분량, 결과는 이 문서의 4장 표를 채우는 것.
